1. Назначение практической работы
Цель работы — освоить методы обработки и анализа текстовых данных средствами Spark MLlib.
В ходе работы необходимо выполнить следующие задачи:
Прочитать корпус текстов средствами Spark.
Подготовить тексты в соответствии с решаемой задачей.
Исследовать частоты слов и представить результаты на графиках.
Построить разреженные векторные представления документов.
Обучить модели классификации текстов и оценить качество их работы.
Завершающий этап посвящён генерации текста. Для этой задачи требуется построить цепи Маркова первого и второго порядка. Затем следует получить новые последовательности слов и разобрать результаты генерации.
В предыдущей работе признаки были заданы столбцами таблицы. Теперь их предстоит выделить из текста. Сначала определим единицы обработки — токены. Затем составим словарь и представим каждый документ числовым вектором. После этого можно переходить к обучению классификатора. Для генерации потребуется другое представление: последовательность слов и частоты переходов между ними.
В работе используется DataFrame-интерфейс pyspark.ml библиотеки MLlib. Представление Bag of Words строится с помощью CountVectorizer. Частоты переходов цепи Маркова подсчитываются средствами Spark DataFrame и NGram. Выбор следующего слова выполняет отдельная функция Python. Таким образом, массовая обработка текстов осуществляется в Spark, а последовательная генерация — в локальной программе.

2.2. Классификация и генерация текста
В задаче классификации объектом анализа служит целый отзыв. Модель определяет вероятности трёх классов. Ответом становится класс с наибольшей вероятностью. Для обучения каждый документ преобразуется в числовой вектор фиксированной длины. В представлении Bag of Words его координаты содержат счётчики слов.
В задаче генерации изучаются переходы между токенами. По короткому предшествующему контексту модель выбирает следующее слово. Здесь существен порядок. Перестановка слов изменяет наблюдаемые переходы. Поэтому тексты для генератора подготовим отдельно.

Обозначим документ через dᵢ, а его длину — через mᵢ. Символ wᵢⱼ обозначает j-й токен i-го документа. Размер словаря равен V. Правило преобразования документа в вектор обозначается φ. 
В качестве токена можно выбрать слово, число, знак препинания или эмодзи. Состав токенов определяется задачей анализа. Эмодзи передают эмоциональную оценку сообщения. В анализе тональности их можно использовать как отдельные признаки.

STAGED = WORK / "rureviews.jsonl"
source_counts = Counter()

with SOURCE.open(encoding="utf-8-sig", newline="") as src, \
     STAGED.open("w", encoding="utf-8", newline="\n") as dst:
    reader = csv.DictReader(src)
    if reader.fieldnames != ["text", "label", "src"]:
        raise ValueError(f"Неожиданные поля: {reader.fieldnames}")
    for row_id, row in enumerate(reader, start=1):

            raise ValueError(f"Повреждена CSV-запись {row_id}")

                      label=float(label), src=row["src"])

Таблица 4. Выбор преобразований текста

Токенизация — выделение последовательности единиц текста. В RegexTokenizer параметр gaps=False задаёт поиск самих токенов по регулярному выражению. Значение minTokenLength=1 сохраняет односимвольные слова. Нижний регистр уже установлен на этапе SQLTransformer. Поэтому в токенизаторе задано toLowercase=False.
Регулярное выражение выделяет слова из русских и латинских букв. Оно сохраняет цифры, внутрисловные дефисы и апострофы. Отдельными токенами становятся группы знаков ! и ?, повторные скобки и перечисленные в шаблоне эмодзи. При работе с другим корпусом состав символов следует задать по его текстам.
Практический блок 4.1. Нормализация и токенизация без обучения словаря
TOKEN_PATTERN = (
    r"[а-яёa-z0-9]+(?:[-’'][а-яёa-z0-9]+)*"
    r"|[!?]+|[()]{2,}"
)

def text_stages():
    return [
        SQLTransformer(statement="""
            SELECT *, lower(coalesce(text, '')) AS text_norm
            FROM __THIS__
        """),
        RegexTokenizer(inputCol="text_norm", outputCol="tokens",
            pattern=TOKEN_PATTERN, gaps=False,
            minTokenLength=1, toLowercase=False)
    ]

text_prep = Pipeline(stages=text_stages()).fit(reviews)
tokenized = text_prep.transform(reviews)
tokenized.select("text", "tokens").show(3, truncate=110)
print("Без распознанных токенов:",
      tokenized.filter(F.size("tokens") == 0).count())
В данном Pipeline находятся только преобразования, которые применяют заранее заданные правила выборки текста сразу в нижнем регистре и токенизацию на основе регулярных выражений до разбиения корпуса. Словарь CountVectorizer и веса IDF будут обучены позднее на выборке train.
После этой токенизации 31 непустой отзыв получает пустой массив токенов. Эти записи остаются в корпусе. Их число будем учитывать при проверке признакового представления.
Группировка повторов и разбиение корпуса
Отзывы с одинаковыми последовательностями токенов объединим в одну группу, идентификатор group_id вычисляется по хешу последовательности. В ключ входят только токены, а метка класса хранится отдельно. Все записи одной группы должны попасть в одну часть выборки.
В результате получено 84 709 групп. В 298 группах встречаются разные метки класса. Все эти наблюдения сохраняются и для каждой группы назначается общее значение split.
Обучающая выборка train предназначена для определения параметров моделей, проверочная выборка valid используется для выбора варианта решения, тестовая выборка test служит для итоговой оценки. Разбиение строится по SHA-256 от group_id и SEED. Первые восемь шестнадцатеричных цифр переводятся в число, остаток от деления на 10 000 определяет часть выборки. В результате получаются приблизительные доли в (70, 15, 15) процентов. После разбиения проверяется наличие трёх классов в каждой части.
Практический блок 4.2. Групповое разбиение на train, valid и test
audit = (tokenized
    .withColumn("group_id", F.sha2(F.concat_ws(" ", "tokens"), 256))
    .withColumn("n_tokens", F.size("tokens")))
groups = audit.groupBy("group_id").agg(
    F.count("*").alias("n"),
    F.countDistinct("label").alias("n_labels"))
print("Групп токенизированных текстов:", groups.count())
print("Групп с противоречивыми метками:",
      groups.filter("n_labels > 1").count())

key = F.sha2(F.concat_ws(":", "group_id", F.lit(str(SEED))), 256)
bucket = F.conv(F.substring(key, 1, 8), 16, 10).cast("long") % 10000
split_df = (audit.withColumn("bucket", bucket)
    .withColumn("split", F.when(F.col("bucket") < 7000, "train")
        .when(F.col("bucket") < 8500, "valid").otherwise("test"))
    .drop("bucket").cache())
split_df.groupBy("split", "label").count().orderBy(
    "split", "label").show()
assert (split_df.groupBy("group_id")
    .agg(F.countDistinct("split").alias("n"))
    .filter("n > 1").count()) == 0

MODEL_COLS = ["row_id", "group_id", "text", "label"]

Отрицания, стоп-слова и морфология
Частица «не» меняет оценку в выражении «товар не хороший». После её удаления получится «товар хороший». Сходный пример — сочетание «не очень хороший». В основной модели сохраним стоп-слова, после чего рассмотрим действие стандартного русского списка стоп-слов, в который данная частица входит под удаление. Для сравнения подготовим список SAFE_STOP, из которого исключены отрицания и несколько слов, изменяющих силу оценки.
Список DISPLAY_STOP используется при построении частотных рисунков. Он скрывает часто встречающиеся фоновые слова. Модель обучается по исходному составу токенов. При определении авторства служебные слова характеризуют особенности речи. В генераторе они сохраняют грамматические связи.

Сопоставьте столбцы tokens, default_stop и safe_stop. Найдите слова, удалённые каждым списком. Обратите внимание на отрицания. В дальнейших опытах сравните три варианта: сохранение всех слов, стандартный список и SAFE_STOP.
Лемматизация заменяет словоформу её словарной формой. Например, слова «товары» и «товаром» приводятся к форме «товар». Стемминг выделяет основу по формальным правилам. Результатом может быть часть слова. Морфологическая нормализация уменьшает разнообразие словоформ в словаре. 
В основном Pipeline морфологическая нормализация не используется. Для отдельного опыта с таким нормализатором потребуется внешняя реализация такого разбора. Его следует загружать один раз на исполнителе и затем применять к обрабатываемым записям.
Влияние морфологической обработки на классификацию проверяют отдельным опытом. Сравнивают качество, размер словаря и время выполнения. Для генерации сохраняются исходные словоформы. Это позволяет воспроизводить сочетания вроде «я купил хороший товар» вместо последовательности лемм «я купить хороший товар». В задаче классификации авторства текста окончания рассматриваются как часть речевого стиля.

6. Bag of Words и TF–IDF как разреженные векторные представления
Словарь и координаты документа
Bag of Words (мешок слов) представляет документ счётчиками токенов. Словарь фиксирует V единиц. Каждой единице соответствует одна координата вектора. Значение координаты равно числу появлений токена в документе. Такой вектор сохраняет кратность вхождений. Порядок следования слов в него не входит. Бинарный вариант хранит значения 0 и 1 по признаку присутствия токена.

Короткий отзыв содержит лишь небольшую часть словаря. Поэтому удобно хранить вектор в разреженной форме. Для этого достаточно указать размерность, индексы ненулевых координат и их значения. Пусть словарь имеет вид [товар, хороший, не, доставка, быстрая]. Тогда документ «товар хороший хороший» представлен вектором [1, 2, 0, 0, 0]. В разреженной записи остаются индексы [0, 1] и значения [1, 2].
Плотная матрица из 86 436 строк и 20 000 признаков типа float64 потребовала бы около 12,9 ГиБ только для чисел. Разреженное хранение существенно сокращает этот объём. В основной обработке сохраним разреженные векторы. Вызов toArray() будем применять лишь к отдельным учебным примерам.
В основном опыте словарь CountVectorizer обучается по train. Для ручного примера зададим пять слов в известном порядке. Метод CountVectorizerModel.from_vocabulary создаёт модель по этому списку. Благодаря фиксированным координатам каждый счётчик легко проверить [4].

Вычисление TF–IDF в Spark
Представление TF–IDF учитывает распространённость токена в обучающем корпусе. В данной работе TF равен числу его вхождений в документ, этот счётчик формирует CountVectorizer. Вес IDF определяется по документной частоте на train. Полученные веса затем применяются к valid, test и новым текстам.
В Spark используется следующая сглаженная формула IDF. В числитель и знаменатель добавляется единица. Для токена, присутствующего во всех обучающих документах, значение IDF равно нулю. При ручной проверке воспользуемся именно этой формулой [4].


Преобразование Normalizer(p=2) делит вектор на его евклидову норму, оно выполняется после расчёта TF–IDF. Нулевой вектор при этом сохраняется. 
В примере N = 3 и для слов «товар» и «хороший» документная частота равна двум, поэтому их IDF = ln(4/3) ≈ 0,287682. Для слов «не», «доставка» и «быстрая» получаем DF = 1 и IDF = ln(2) ≈ 0,693147. Вектор документа d0 после взвешивания имеет две ненулевые координаты  и . После L2-нормирования они равны приблизительно 0,447214 и 0,894427, а остальные координаты равны нулю.
Практический блок 6.2. Ручная проверка TF–IDF и нормирования

Биграммы и хеширование признаков
Биграмма — пара соседних токенов. Из выражения «товар не хороший» получаются биграммы «товар не» и «не хороший». Добавим их к отдельным словам, или униграммам, тогда сочетание «не хороший» получит собственную координату.
В основном классификаторе биграммы строятся по последовательности токенов целого отзыва, это выполняется до удаления стоп-слов. Например, удаление «очень» из фразы «не очень хороший» создаёт новое соседство «не хороший». Для отдельного опыта с биграммами внутри предложений сначала потребуется выделить границы предложений.
HashingTF сопоставляет каждому токену одну из заранее заданных координат, при этом явный словарь не обучается. Если два токена получают одну координату, их счётчики складываются, такое совпадение называют коллизией. Параметр numFeatures задаёт размерность вектора и его увеличение снижает вероятность таких коллизий. В соответствии с рекомендацией API используем степень двойки [4].
Практический блок 6.3. Биграммы и хеширование признаков

toy_bigrams.select("tokens", "bigrams").show(truncate=False)

                    numFeatures=2**16, binary=False)

HashingTF рассмотрен как альтернативный способ векторизации, в то время как основные модели используют CountVectorizer. Его словарь связывает координаты с конкретными словами. При обработке нового текста учитываются токены из обученного словаря. Долю остальных вхождений обозначают OOV, и далее подсчитаем её отдельно.
7. Классификация текста
Наивный Байес для счётчиков слов
Мультиномиальный наивный байесовский классификатор работает со счётчиками токенов. Для каждого класса он оценивает вероятности слов. Затем вычисляет оценку принадлежности документа каждому классу. В основе модели лежит предположение об условной независимости вхождений при заданном классе. Оно позволяет объединить отдельные вероятности в простую вычислительную схему.
Через  обозначим число вхождений токена j в обучающих документах класса k. Величина  равна общему числу учитываемых вхождений этого класса. Сглаживание с параметром  добавляет к счётчикам единицу. Благодаря этому для отсутствовавшего слова получается положительная оценка вероятности. Априорные вероятности классов также определяются по train. В дискретных вариантах NaiveBayes библиотека Spark применяет сглаживание и к частотам классов [5].

Модель выбирает класс с наибольшей оценкой . Мультиномиальная модель учитывает число повторений слова, а модель Бернулли использует только признак его присутствия. В данной работе выбран мультиномиальный вариант.
Модель NB_BOW служит первым обучаемым решением, дополнительно построим постоянное правило, когда всем документам назначается наиболее частый класс train. Его результат будет исходным уровнем сравнения.
Мультиномиальная логистическая регрессия
Для трёх классов логистическая регрессия использует функцию softmax. Каждому классу соответствует линейная оценка zₖ = bₖ + wₖᵀx. Функция softmax преобразует эти оценки в вероятности, и их сумма равна единице. Итоговый ответ определяется по наибольшей компоненте полученных оценок вероятностей:


Первое слагаемое функции потерь  увеличивается при уменьшении вероятности правильного класса . Второе слагаемое задаёт L2-регуляризацию коэффициентов для сдерживания роста их величин при обучении. Свободные члены bₖ в этот штраф не входят.
Модель линейна по координатам подготовленного вектора. Биграмма входит в него как самостоятельный признак сочетания слов. Для явного контроля масштаба зададим standardization=False. В модели будут использованы либо счётчики BoW, либо отдельно нормированные значения TF–IDF.

Параметр minDF = 3.0 оставляет токены, встречающиеся не менее чем в трёх документах. Параметр vocabSize = 20000 задаёт верхнюю границу размера словаря. Фактический словарь сохраняется в обученной модели.
В вариантах TF–IDF после подсчёта вхождений выполняются IDF и Normalizer. Для модели с биграммами SQLTransformer объединяет два массива признаков, классификатор обучается по столбцу features, а целевая метка находится в label. Идентификаторы row_id и group_id остаются служебными полями.
Практический блок 7.1. Построение четырёх цепочек Pipeline
SPECS = ["NB_BOW", "LR_BOW", "LR_TFIDF", "LR_TFIDF_BIGRAM"]
VOCAB_SIZE = 20000
MIN_DF = 3.0
REG_PARAM = 0.001

def make_pipeline(name, stop_words=None, reg_param=REG_PARAM):
    if name not in SPECS:
        raise ValueError(name)
    stages = text_stages()
    input_col = "tokens"
    if stop_words is not None:
        if name == "LR_TFIDF_BIGRAM":
            raise ValueError("Биграммы нельзя строить после удаления слов")
        stages.append(StopWordsRemover(inputCol="tokens",
            outputCol="filtered", stopWords=stop_words))
        input_col = "filtered"
    if name == "LR_TFIDF_BIGRAM":
        stages += [NGram(n=2, inputCol="tokens", outputCol="bigrams"),
            SQLTransformer(statement="""
                SELECT *, concat(tokens, bigrams) AS terms
                FROM __THIS__
            """)]
        input_col = "terms"
    use_idf = "TFIDF" in name
    count_col = "counts" if use_idf else "features"
    stages.append(CountVectorizer(inputCol=input_col,
        outputCol=count_col, vocabSize=VOCAB_SIZE,
        minDF=MIN_DF, binary=False))
    if use_idf:
        stages += [IDF(inputCol="counts", outputCol="tfidf"),
            Normalizer(inputCol="tfidf", outputCol="features", p=2.0)]
    if name == "NB_BOW":
        classifier = NaiveBayes(modelType="multinomial", smoothing=1.0)
    else:
        classifier = LogisticRegression(family="multinomial",
            maxIter=200, tol=1e-6, regParam=reg_param,
            elasticNetParam=0.0, standardization=False)
    return Pipeline(stages=stages + [classifier])
В основном опыте сравниваются четыре модели с заданными параметрами. Для логистической регрессии принято λ = 0,001. При дополнительном подборе регуляризации каждый способ представления текста рассматривается отдельно. Значение параметра выбирается по valid части выборки.
Метрики для трёх классов
Матрица ошибок C сопоставляет истинные и предсказанные классы, строки соответствуют истинным меткам, столбцы соответствуют ответам модели. На главной диагонали стоят числа верных предсказаний, сумма строки nₖ равна числу объектов класса k, сумма столбца mₖ равна числу предсказаний этого класса. Показатель precision характеризует долю верных решений среди ответов класса k, показатель recall характеризует долю найденных объектов этого класса.


Для выбора модели используется macro-F1. Этот показатель усредняет F1 трёх классов с одинаковыми весами. В weighted-F1 вес класса равен его доле в выборке. В MulticlassClassificationEvaluator параметр metricName="f1" соответствует взвешенному варианту. Ниже оба показателя вычисляются по матрице ошибок, при нулевом знаменателе код возвращает нулевое значение метрики.
Логарифмическая функция потерь log loss оценивает вероятности правильных классов. Чем меньше её значение, тем лучше результат. Уверенное ошибочное предсказание даёт большой вклад в потери. Перед вычислением логарифма вероятность ограничивается снизу значением 10⁻¹⁵. Это обеспечивает численную устойчивость.

Функция multiclass_metrics подсчитывает матрицу ошибок средствами Spark. Для K = 3 она содержит не более девяти ячеек. Только эта небольшая таблица передаётся в NumPy. Вероятность правильного класса извлекается из столбца probability. В функции element_at индексация начинается с единицы. Поэтому к значению label прибавляется 1.
Практический блок 7.2. Матрица ошибок, macro-F1 и log loss
def multiclass_metrics(pred, k=3):
    cells = pred.groupBy("label", "prediction").count().collect()
    cm = np.zeros((k, k), dtype=np.int64)
    for row in cells:
        cm[int(row.label), int(row.prediction)] = row["count"]
    if cm.sum() == 0:
        raise ValueError("Пустая выборка для оценки")
    support = cm.sum(axis=1)
    predicted = cm.sum(axis=0)
    tp = np.diag(cm).astype(float)
    precision = np.divide(tp, predicted, out=np.zeros(k), where=predicted > 0)
    recall = np.divide(tp, support, out=np.zeros(k), where=support > 0)
    f1 = np.divide(2 * precision * recall, precision + recall,
        out=np.zeros(k), where=(precision + recall) > 0)
    by_class = pd.DataFrame(dict(label=range(k), support=support,
        precision=precision, recall=recall, f1=f1))
    metrics = dict(accuracy=float(tp.sum() / cm.sum()),
        macro_f1=float(f1.mean()), weighted_f1=float(f1 @ support / cm.sum()))
    if "probability" in pred.columns:
        scored = pred.withColumn("_p", vector_to_array("probability"))
        true_p = F.expr("element_at(_p, cast(label as int) + 1)")
        metrics["log_loss"] = float(scored.agg(F.avg(-F.log(
            F.greatest(true_p, F.lit(1e-15))))).first()[0])
    return metrics, by_class, cm

train_counts = train.groupBy("label").count().orderBy(

Обучение на train и сравнение на valid
Вызов fit(train) запускает обучение всей цепочки. Сначала строится словарь. При наличии этапа IDF рассчитываются веса токенов. Затем обучается классификатор. Выполнение одного Pipeline.fit может включать несколько Spark Jobs. Этапы Pipeline описывают последовательность аналитических операций. Spark Stages относятся к физическому плану вычислений [6].
Метод setJobGroup задаёт подписи опытов в Spark UI. Функция perf_counter измеряет время обучения всей цепочки. Расчёт метрик выполняется после этого измерения. Предсказания на valid сохраняются в кэше для повторного использования. Результаты упорядочиваются по macro-F1. При равенстве показателя используется имя модели.

Сравнение коэффициентов классов
Для мультиномиальной логистической регрессии рассмотрим разность коэффициентов двух классов. В данном примере сравниваются положительный и отрицательный классы (w₁ − w₂). Эта разность связана с логарифмом отношения их вероятностей. При фиксированных остальных координатах она показывает вклад выбранного признака в различение двух классов. Общая добавка ко всем линейным оценкам сокращается при вычислении softmax.
Для этого примера используется ранее обученная модель LR_TFIDF, матрица её коэффициентов имеет размер K × V, в данном опыте K = 3, а V не превышает 20000. Перенесём эту матрицу в Python и по словарю модели сопоставим коэффициенты с токенами.

10. Базовая модель языка на цепях Маркова
Состояния и вероятности переходов
Цепь Маркова строит продолжение по предшествующему контексту. В модели первого порядка учитывается один последний токен. В модели второго порядка учитываются два токена. Состоянием второй модели служит их упорядоченная пара. После выбора нового слова пара сдвигается на одну позицию [10].


В формуле h обозначает состояние. Счётчик c(h, w) показывает число продолжений словом w после этого состояния. Пусть контекст встретился пять раз. В трёх случаях за ним следовало слово «хороший», в двух — «плохой». Тогда вероятности равны 3/5 и 2/5. Генератор случайно выбирает один из вариантов с этими весами.
Токен <BOS> обозначает начало предложения, а токен <EOS> обозначает его конец. Перед предложением для модели второго порядка ставятся два токена <BOS>. Переходы подсчитываются отдельно внутри каждого предложения, и границы отзывов также сохраняются.

При увеличении порядка модель учитывает более длинный контекст. Одновременно возрастает число редких состояний. Для нового сочетания слов используется переход к более короткому контексту, или backoff. Если пара отсутствует в таблице, программа ищет последнее слово, если отсутствует и оно, выбирается начальное состояние.

def count_transitions(sentence_df, order):
    if order not in (1, 2):
        raise ValueError("В этой работе поддерживаются порядки 1 и 2")
    padded = sentence_df.withColumn("seq", F.concat(
        F.array(*[F.lit("<BOS>") for _ in range(order)]),
        F.col("words"), F.array(F.lit("<EOS>"))))
    grams = NGram(n=order + 1, inputCol="seq", outputCol="grams").transform(padded)
    edges = grams.select(F.explode("grams").alias("gram"))
    parts = F.split("gram", " ")
    return (edges.select(F.lit(order).alias("order"),
        F.concat_ws(" ", F.slice(parts, 1, order)).alias("context"),
        F.element_at(parts, order + 1).alias("next"))
        .groupBy("order", "context", "next").count())

transitions = count_transitions(sentences, 1).unionByName(
    count_transitions(sentences, 2)).cache()

Функция build_chain преобразует таблицу в словарь переходов. Ключ содержит порядок модели и контекст, а значение содержит варианты следующего токена и их счётчики. Выбор производится среди переходов, имеющихся в таблице. Для устойчивого вычисления весов используются логарифмы и вычитание максимального значения.

Генерация завершается при появлении <EOS>, либо когда получено max_tokens новых токенов. Длина входного префикса учитывается отдельно. Счётчик backoffs показывает число обращений к короткому контексту. В конце удаляются пробелы перед выбранными знаками препинания.
Практический блок 10.3. Генерация с переходом к короткому контексту
def build_chain(edge_records):
    chain = defaultdict(list)
    for r in edge_records:
        key = (int(r["order"]), tuple(r["context"].split(" ")))
        chain[key].append((r["next"], int(r["count"])))
    return {key: sorted(value) for key, value in chain.items()}

def generate(chain, prompt="", order=2, max_tokens=40,
             seed=42, temperature=1.0):
    if (order not in (1, 2) or max_tokens < 1 or
        not math.isfinite(temperature) or temperature <= 0):
        raise ValueError("Некорректные параметры генерации")
    rng = random.Random(seed)
    pattern = MARKOV_PATTERN.replace("(?U)", "")
    prefix = re.findall(pattern, prompt.lower())
    history = ["<BOS>"] * order + prefix
    result, backoffs = [], 0
    reason = "max_tokens"
    for _ in range(max_tokens):
        context = tuple(history[-order:])
        options = chain.get((order, context))
        if not options and order == 2:
            options = chain.get((1, (history[-1],)))
            backoffs += 1
        if not options:
            options = chain.get((order, ("<BOS>",) * order))
            backoffs += 1
        if not options:
            raise ValueError("В цепи нет стартового состояния")
        words, counts = zip(*options)
        logs = [math.log(c) / temperature for c in counts]
        maximum = max(logs)
        weights = [math.exp(x - maximum) for x in logs]
        word = rng.choices(words, weights=weights, k=1)[0]
        if word == "<EOS>":
            reason = "eos"
            break
        result.append(word)
        history.append(word)
    text = " ".join(prefix + result)
    text = re.sub(r"\s+([.,!?;:])", r"\1", text)
    return dict(text=text, generated_tokens=len(result),
                backoffs=backoffs, stopped_by=reason)

chain = build_chain(edge_rows)

literature = spark.read.schema("""
        document_id STRING, folder STRING, author STRING,
        filename STRING, text STRING, work_group STRING
    """).json(LIT_JSON.as_posix())

docs = chosen.join(literature.select("document_id", "text"), "document_id")
docs = docs.withColumn("body", F.expr(
        "substring(text, body_start + 1, body_end - body_start)"))
units = docs.select("author", "work_group").distinct()

w = Window.partitionBy("author").orderBy(F.sha2("work_group", 256))
wa = Window.partitionBy("author")
units = (units.withColumn("r", F.row_number().over(w))
        .withColumn("n", F.count("*").over(wa))
        .withColumn("split", F.when(F.col("r") <= F.floor(F.col("n") * .6), "train")
            .when(F.col("r") <= F.floor(F.col("n") * .8), "valid")
            .otherwise("test")).select("author", "work_group", "split"))
docs = docs.join(units, ["author", "work_group"])


word_tokenizer = RegexTokenizer(inputCol="body", outputCol="words",
        pattern=r"(?U)[^\W_]+", gaps=False, minTokenLength=1)
docs = word_tokenizer.transform(docs).filter(F.size("words") >= 300)
fragments = (docs.withColumn("start", F.explode(
        F.sequence(F.lit(1), F.size("words") - 299, F.lit(300))))
        .withColumn("fragment", F.expr("slice(words, start, 300)"))
        .withColumn("text_fragment", F.concat_ws(" ", "fragment")))
fragments.groupBy("author", "split").count().show()

Идентификатор фрагмента образуют document_id и start. Целевая переменная — author. Остальные идентификаторы используются для группировки и проверки результатов.
